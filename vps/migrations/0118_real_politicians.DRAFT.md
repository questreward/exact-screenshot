## Existing storage audit (repository, not live database)

- `build_legislatives_2024.py` parses Interior Ministry 2024 round CSVs and deliberately hashes constituency into invented names. Writes 0057 and `public/geo/legislatives-2024.json`. 0057: `legislative_parties(code,label,color,bloc,organization_id)` stores **electoral nuances**, not contemporary parliamentary groups; `legislative_constituencies` has code/department/number/registration/map/city metadata; `legislative_baseline_2024` stores votes by code/round/nuance; `legislative_deputies_2024` stores code → party_code + invented display_name. Preserve historical election results.
- `build_legislatives_577.py` generates 0058 from baseline and existing VPS parliamentary function definitions (`tools/data/parlement_vps.sql`). 0058 expands Assembly seats from 50 to 577, adds `national_groups.party_code` FK to nuances, `national_seats.constituency_code`, and `display_name`; creates `legislative_settings`, elections, candidacies, ballots and results. Baseline seeding fills simulated seats using invented names. Player elections use 2024 weights, seeded noise, affinity transfers and `legislative_invented_name`; they are game outcomes, not actual elections.
- `national_legislatures`/`national_elections` provide game calendar. `national_groups` groups seats by legislature/chamber with organization, name, support and now nuance code. `national_seats` links legislature/chamber/seat_no/group to optional player character or NPC, `simulated`, city and constituency; a name can exist without NPC. These are game entities, not a factual person registry. Current group labels and parties must not be conflated with nuance codes.
- 0045 activates national politics and defines `national_law_positions(template_id,party_key,vote)` with PK template+party, `yes/no` CHECK, RLS authenticated read. Initially five fictional-party lines. Its tick explicitly forms a fictional government of **six NPCs**. `national_governments` stores legislature, government number, majority group, dates; `national_offices` stores government, role (president/prime_minister/minister), ministry, NPC, display_name, dates. `national_form_government` enforces exactly president + PM + four distinct ministers, all NPCs; this cannot represent the real cabinet without redesign. 0058 replaces this function but retains the six-NPC contract.
- `real_laws.py`/0055 seed 100 templates (60 law-inspired reinforcement proposals + 40 reforms), add kind/reference/summary, deactivate but retain five fictional laws, and seed 500 **invented heuristic** party positions. Python `vote()` uses S/P/E/L/A/C tags, not recorded divisions. 0103 adds more French-law-inspired templates/positions. 0058 populates nuance-based positions too. None is evidence of a real person's vote.
- 0058 `national_close_session` loops snapshot electorate seat IDs, reads player `national_parliamentary_votes`, otherwise `national_law_positions` by template and `COALESCE(group.party_code,organization_id::text,'divers')`. Missing votes fall into abstention; tallies stored on `national_sessions`; status feeds `national_laws`/activities. It does not model split group votes, non-voting, sourcing or abstention as independent evidence.
- Frontend: `src/routes/_authenticated/_game/france.tsx` reads the static map and overlays live seat names/nuances. `src/components/game/LegislativesPanel.tsx` displays player candidacy/results and simulated candidates. `src/game/legislatives.ts` defines seats/majority. `src/routes/_authenticated/_game/politique.tsx` and `politique_.$id.tsx` are politics routes; service layer `src/services/game.ts` exposes legislative queries/actions. There is no separate factual current-person feed. Do not silently relabel simulated game winners as sitting real MPs.

## Proposed SQL design — not executable, not applied

New read-only, versioned factual namespace (names illustrative):

1. `political_sources(id,url,retrieved_at,published_at,sha256,license,archive_member)` and `political_snapshots(id,as_of,source_id,status,validation_report)`; do not hardcode expected persons=577.
2. `real_politicians(id,an_actor_uid UNIQUE,display_name)`; no stats, invented biographies, quotes or personal traits.
3. `real_parliamentary_groups(id,an_organe_uid,label,short_label,valid_from,valid_to)` separate from `legislative_parties` electoral nuances. `real_parties` similarly independent; no automatic ideological mapping.
4. `real_deputy_mandates(id,person_id,constituency_code,an_mandate_uid,since,until,replaces_mandate_uid,election_cause,snapshot_id)`; FK existing constituency; prohibit overlapping occupants. `real_group_memberships` / `real_party_attachments` dated evidence, capacity and semantics. Unknown attachments stay unknown.
5. `real_offices(person_id,role,portfolio,valid_from,valid_to,source_id,snapshot_id,verification_status)` for presidency, variable-size cabinet and party leadership, independent of game `national_offices`.
6. `real_scrutins(id,an_uid,date,title,text_version,stage,source_id)` + `real_group_vote_counts(scrutin_id,group_id,pour,contre,abstention,non_votant,absent)`; optionally official group lines with date, exact policy scope and URL. Never infer missing/absent=abstention. Use official scrutins open data, not election nuance or ideology.
7. `simulation_law_evidence(template_id,template_version,group_id,scrutin_id_or_group_line,polarity,scope_note,reviewed_by,reviewed_at,valid_from,valid_to,method_version)` with human review. `simulation_vote_outputs(session_id,seat_id,position,evidence_id,label)` stores **« simulation »** and provenance; unknown is not a vote. Historical group identity is retained even if a party later moves.

Adapt `national_close_session` for evidence-backed simulation and distinct unknown/non-voting, snapshot electorate group/evidence, remove heuristic fallback for factual mode. ## How people act: educational « simulation » only

- Factual reference panel shows dated offices/group membership and sources; simulated gameplay panel always says **« simulation — projection de la position du groupe, pas vote réel de cette personne »**.
- Only use an exact, reviewed relation between a game law's wording/version and a real recorded group division or explicit official group line. A vote to enact an original law is **not** evidence for a new “Renforcer” template, repeal, amendment, or later reform. No evidence ⇒ “position non documentée”, no generated yes/no and no silent abstention. Disable factual-mode resolution until its missing-evidence policy is explicitly approved.
- Where a real group is split, display counts/distribution; no claim of unanimity. Any distribution-based game projection is a labeled aggregate simulation with published method/seed, never historical individual attribution. Apparentés/non-inscrits need their own evidence; no default party line.
- Real recorded votes remain historical facts in separate records. Sources are date/legislature/text-stage specific; not transferable across reorganized groups without review. No invented quotes, conversations, motives, promises or ministerial game actions attributed to real people.
- This deliverable intentionally has **zero simulation vote positions**: importing all existing heuristic votes under real names would be false attribution.
